# AWS S3 media setup

Homepage images (`public/assets/images`) and product/category uploads (`public/uploads`) can be served from S3. Admin uploads go to S3 automatically when AWS env vars are set.

## 1. Bucket

1. Create an S3 bucket (example region: `ap-south-1`).
2. Enable **Block Public Access** if you will use CloudFront with OAC, **or** add a public-read bucket policy for object gets if using the S3 website/object URL directly.
3. Optional: put CloudFront in front of the bucket and use that URL as the media base.

Public-read policy example (only if not using CloudFront private origin):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/*"
    }
  ]
}
```

IAM user needs at least `s3:PutObject`, `s3:DeleteObject`, `s3:GetObject`, `s3:ListBucket`, `s3:HeadBucket` on that bucket.

## 2. Env (`web/.env`)

```dotenv
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=ap-south-1
AWS_S3_BUCKET=your-bucket-name
NEXT_PUBLIC_MEDIA_BASE_URL=https://your-bucket-name.s3.ap-south-1.amazonaws.com
```

Use your CloudFront domain for `NEXT_PUBLIC_MEDIA_BASE_URL` when available. Restart / rebuild after changing it.

## 3. Migrate existing files

From `web/`:

```sh
node scripts/migrate-images-to-s3.mjs
```

Uploads:

- `public/assets/images/**` → `assets/images/...`
- `public/uploads/products/**` → `uploads/products/...`
- `public/uploads/categories/**` → `uploads/categories/...`

Keys stay the same so DB product paths like `uploads/products/....jpg` keep working through `imgSrc()`.

## 4. App behavior

- `imgSrc()` / `assetImage()` prefix relative paths with `NEXT_PUBLIC_MEDIA_BASE_URL`.
- Admin product/category uploads call S3 when AWS vars are present; otherwise they still write to local `public/uploads`.
- Without AWS vars, the site keeps using local `/assets` and `/uploads` files.
