# AWS S3 media setup

Admin uploads go to the `rareobjet-media` bucket folders when AWS env vars are set. DB stores relative keys; the storefront builds URLs with `NEXT_PUBLIC_MEDIA_BASE_URL`.

| Admin | S3 / DB key prefix |
|---|---|
| Products | `products/` |
| Categories | `category/` |
| Homepage media | `banner/` |
| Seeded homepage defaults | `assets/images/` (until replaced) |

## 1. Bucket

1. Create an S3 bucket (example: `rareobjet-media` in `ap-southeast-2`).
2. Enable **Block Public Access** if you will use CloudFront with OAC, **or** add a public-read bucket policy for object gets if using the S3 object URL directly.
3. Optional: put CloudFront in front of the bucket and use that URL as the media base.

Public-read policy example (only if not using CloudFront private origin):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/*"
    }
  ]
}
```

IAM user needs at least `s3:PutObject`, `s3:DeleteObject`, `s3:GetObject`, `s3:ListBucket`, `s3:HeadBucket` on that bucket.

## 2. Env (`web/.env`)

```dotenv
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=ap-southeast-2
AWS_S3_BUCKET=rareobjet-media
NEXT_PUBLIC_MEDIA_BASE_URL=https://rareobjet-media.s3.ap-southeast-2.amazonaws.com
```

- `AWS_REGION` must be the region **code** only (`ap-southeast-2`), not a display name.
- `NEXT_PUBLIC_MEDIA_BASE_URL` is the **bucket root** only — do **not** append `/banner/` or `/products/`.
- Paste credentials yourself; never commit real secrets. Restart / rebuild after changing env.
- **Private buckets:** the storefront/admin load images via `/api/media/...` (app uses AWS credentials). Uploads still go to S3; DB stores relative keys. You do **not** need a public bucket for previews to work.
- Optional: set `NEXT_PUBLIC_MEDIA_DIRECT=1` only if the bucket/CloudFront URL is publicly readable and you want browsers to hit S3/CDN directly.

Also copy the same `AWS_*` + `NEXT_PUBLIC_MEDIA_BASE_URL` values into `.env.production` for Hostinger (empty production AWS vars override local `.env` in production mode).

Use your CloudFront domain for `NEXT_PUBLIC_MEDIA_BASE_URL` when available.

## 3. Migrate existing files

From `web/`:

```sh
node scripts/migrate-images-to-s3.mjs
```

Uploads:

- `public/assets/images/**` → `assets/images/...`
- `public/products/**` → `products/...`
- `public/category/**` → `category/...`
- `public/banner/**` → `banner/...`
- Legacy `public/uploads/...` is also uploaded if present

If older DB rows still use `uploads/...` paths, run [`sql/migrations/002_s3_path_prefixes.sql`](sql/migrations/002_s3_path_prefixes.sql).

## 4. App behavior

- `imgSrc()` / `assetImage()` prefix relative paths with `NEXT_PUBLIC_MEDIA_BASE_URL`.
- Admin product → `products/{file}`; category → `category/{file}`; homepage → `banner/{file}` on S3 (or the same under `public/` when AWS is off).
- Admin **Homepage media** (`/admin/homepage`) stores paths in `site_media`. Seeded defaults remain `assets/images/...` until replaced.
- After checkout, order confirmation HTML is archived at `orders/user-{userId}/order-{orderId}/confirmation.html`.

Apply `site_media` with `web/sql/migrations/001_site_media.sql` (or rely on the app’s `CREATE TABLE IF NOT EXISTS` + seed on first homepage/admin load).
